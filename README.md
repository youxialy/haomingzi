# 实习日报一点通

面向顶岗实习学生的报告生成工具：一次配置岗位，之后**每天 30 秒生成日报**，周报、月报、实习总结从日报**一键自动汇总**。数据只存本地浏览器，无账号、无服务器、无上传。

> 参照《沧州职业技术学院-实习系统-学生操作手册》设计：覆盖学习通实习系统里的 **日报 / 周报 / 月报 / 总结** 四类报告；周报月报按批次时间窗提交、过期可能不能补交的特点用「今日该交」提醒面板应对。

## 快速开始

**本地使用**：直接双击 `index.html` 即可（无需安装任何东西）。

**首次使用（5 分钟）**：
1. 打开页面 → 点横幅「去配置」
2. 选岗位类型（28 种，覆盖主流实习方向：电商客服 / 行政文员 / 销售 / 工厂技术 / 电子厂·普工质检 / 护理 / 幼师 / 餐饮酒店 / 新媒体运营 / 平面设计 / 会计财务 / 物流仓储 / 物业管理 / 房产置业顾问 / 药店营业员 / 汽车维修 / 导游景区 / 美容美发 / 银行大堂助理 / 软件开发实习 / 施工监理 / 门店零售 / 翻译文员 / 农业技术 / 师范·教师实习 / 人力资源·HR助理 / 电商运营助理 / 通用）
3. 勾选你**真实**的工作模块（可自定义补充），填实习起止日期和字数要求
4. 回「今日日报」→ 点「✨ 生成日报」→ 复制 → 粘贴到学习通提交

**每天（30 秒）**：生成日报 → 复制 → 学习通「上班打卡」→ 粘贴提交日报。

## 功能一览

| 页签 | 功能 |
|---|---|
| 今日日报 | 按日生成/编辑/保存，特殊事项合并，字数统计与达标提示，「换一版」一键换措辞，一键复制，标记已提交；手动改过内容后重新生成会先确认 |
| 周报月报 | 本周/上周、本月/上月或自定义区间，从日报自动汇总成稿，可编辑/复制/打印；留档记录可随时载入或删除 |
| 实习总结 | 汇总全部日报，生成五章结构总结（概况/主要工作/收获/不足/结语） |
| 日历·待办 | 月历查看提交状态，点日期补写；**批量补写缺失日报**（自动找出漏写的工作日一键补齐）；待办清单（含"学习通上班打卡"快捷项） |
| 素材库 | 按场景分类的写作句式，可一键复制或插入今日日报，支持自建收藏 |
| 设置 | 岗位配置、日报栏目自定义（改名/关闭，适配各校模板）、周报/月报批次截止提醒（首页倒计时）、JSON 导出/导入备份、清空数据 |

## 使用边界（务必阅读）

- 本工具自动**写**报告（汇总、成文、排版），工作模块请如实配置——报告内容真实性由使用者自己负责；
- **不做也不建议使用**自动打卡 / 代签 / 脚本刷课：收集他人账号凭证涉嫌侵犯公民个人信息，脚本绕过平台涉嫌非法获取计算机信息系统数据，均已有追责先例。本工具是纯写作辅助，与平台无任何自动化交互；
- 每天手动打卡 + 工具写报告 = 省时且安全。

## 传播方案（按优先级）

1. **班级实习群冷启动**：发给同班同学，一句话介绍"配一次岗位，以后日报周报自动写"。同学的真实反馈是第一轮迭代依据；
2. **小红书 / 知乎**：在"实习日报怎么写""实习周报模板""顶岗实习"等话题下发内容（把 guide.html 的指南改写成笔记），工具链接放评论或主页；
3. **SEO 长线**：guide.html 承接"实习日报怎么写 / 周报模板 / 月报模板"等搜索词；部署后到 [Google Search Console](https://search.google.com/search-console) 和[百度站长平台](https://ziyuan.baidu.com)提交 `sitemap.xml`；
4. **每年两批实习季**（春 / 秋）需求自然回潮，老内容持续有效。

## 测试

双击 **`跑测试.bat`** 一键跑全部五套；或 `npm test`；或分别执行：

```bash
node test/harness.js          # 28 项断言  生成引擎
node test/draft.test.js       # 23 项断言  草稿暂存
node test/backup.test.js      # 62 项断言  备份码 / 导入校验
node test/integration.test.js # 82 项断言  真机冒烟（自动查找 jsdom，找不到才跳过）
node test/repetition.test.js  # 51 项断言  内容防重复回归（M1~M11）
```

合计 **246 项断言**。前四套零依赖，直接在 Node 里跑；`integration.test.js` 需要 jsdom
（`npm i` 后自动可用，或按 env `HMZ_JSDOM` → 项目内 `node_modules` → WorkBuddy 隔离工作区 的顺序自动查找）。

**发布前最该跑 `integration.test.js`**：它把 `index.html` 连同 7 个脚本真实执行一遍，
并模拟「配置岗位 → 生成 → 保存 → 切日期 → 导出 → 导入 → 换主题 → 开弹窗」整条链路，
能抓住「静态检查抓不到、只有运行才暴露」的问题（绑错元素、回调抛错、导入后渲染炸掉）。

**改了生成相关内容必跑 `repetition.test.js`**：它把内容防重复的 11 项指标（M1~M11）阈值固化，
指标回退会直接红掉（例如把防重窗口改小、把句式池删条、把版式骨架删掉、把配置指纹从随机种子里去掉）。

## 发布前必读：改版本号

站点靠 `?v=YYYYMMDDNN` 做缓存失效，**改完静态文件必须同步升级版本号**，否则老用户拿不到新代码。

共 **10 处**要同步（手工容易漏），用脚本一次改完：

```bash
node tools/bump-version.js 2026091901   # 指定版本号
node tools/bump-version.js              # 省略参数 = 按当天日期自动生成 YYYYMMDD01
node tools/bump-version.js --dry-run    # 只预览会改哪些位置，不落盘
```

脚本覆盖：
1. `index.html` / `guide.html` 里所有 `?v=xxx`（css + 7 个 js，共 9 处）
2. `sw.js` 顶部的 `VERSION`（1 处）

`sw.js` 的 `activate` 会自动删掉旧版本缓存。

## 备份码格式

- 现用：`IR2:` + base64(LZ 压缩后的紧凑 JSON)。比旧格式小 **20~30 倍**（一年日报约 26 KB，旧格式 840 KB）。
- 兼容：`IR1:`（旧版 base64 JSON）与直接粘贴裸 JSON 仍可导入，老用户不丢数据。
- 容错：粘贴时自动忽略换行、空格、`第N/M段：` 分段标记和重复前缀，所以分几条微信发给自己也能恢复。
- 安全：导入的数据一律按不可信输入校验（结构不对拒绝；个别条目坏了丢弃并计数上报）；
  渲染模块名 / 岗位名 / 留档信息一律用 `textContent`，不拼 `innerHTML`。
